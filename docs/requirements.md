# トチカン 要件定義書

> この文書は要件定義の段階でまとめたもの。技術構成の案は12章、進め方は13章にまとめた。
> 「決定」と書いたものは合意済み、「案」と書いたものは方針として採用しているが詳細は未確定。

## 1. 概要

東京の駅の位置と路線を、すごろくで遊びながら覚えるスマホ向けWebアプリ。

- アプリ名：トチカン（「土地勘」から）（決定）
- リポジトリ名：`tochikan`（決定）
- 形態：スマホ対応のWebアプリ（縦画面が基本）
- 公開範囲：一般公開し、誰でも使えるようにする（決定）
- 見た目：かわいい雰囲気にする

## 2. 目的

会話で駅名を聞いたときに、次の2つがわかるようになること。

1. その駅が地図上のだいたいどこにあるか
2. そこへ行くにはどの路線を使えばよいか

## 3. 想定ユーザー

- 東京の地理が苦手な人（上京した人、仕事で東京に行く人など）
- 通勤中などのすき間時間に、スマホで遊ぶ

## 4. 対象範囲

### 4.1 対象の駅（決定）

- 東京都内にある駅だけを対象にする
- 路線は都県境で打ち切る（例：中央線は都内の駅まで）

### 4.2 対象の路線（決定）

東京都内を走る全路線。

- JR
- 東京メトロ
- 都営地下鉄
- 私鉄各線（京王、小田急、東急、西武、東武、京急、京成など）
- モノレール、新交通システム（東京モノレール、多摩モノレール、ゆりかもめ、日暮里・舎人ライナーなど）
- 都電荒川線
- その他、都内に駅がある路線（りんかい線、つくばエクスプレスなど）

※ 最終的な路線一覧は、採用する駅データから確定する。

### 4.3 都外を通る区間の扱い（決定）

いったん都外に出て、また都内に戻る路線がある。

- 例：小田急線（登戸の先で神奈川県に出て、鶴川で都内に戻る）
- 例：東急田園都市線（二子玉川の先で出て、南町田グランベリーパークで戻る）
- 例：JR横浜線（町田のあたりで都内と神奈川県を行き来する）

扱い：

- 都外の駅も盤面に置く
- ただし「通過するだけのマス」にする。そこには止まらず、出題もしない
- 都外の駅は、都内の駅と見た目で区別できるようにする

## 5. 機能要件

### FR-01 すごろくモード（メインの遊び）（決定）

基本の流れ：

1. お題（ゴール駅）が出る。例：「吉祥寺でお茶しよう！」
2. スタート駅が決まる
3. サイコロを振り、今いる路線で出た目の数だけ進む。進む方向はプレイヤーが選ぶ
4. 止まる駅を予想し、地図上でタップする（FR-02）
5. 正解すると、その駅にスタンプが押され、地図に色がつく（FR-04、FR-05）
6. 乗換駅に止まったら、別の路線に乗り換えられる
7. ゴール駅に着いたら終了。少ないターンで着くほど高得点

未決事項：

- お題とスタート駅の決め方（ランダムか、難易度に合わせて選ぶか）
- サイコロの目の範囲（1〜6でよいか）
- ゴール駅を通り過ぎる場合の扱い（ちょうど止まる必要があるか）
- 終点で目が余った場合の扱い
- 点数の計算方法

### FR-02 止まる駅の予想（位置クイズ）（決定）

- プレイヤーは、止まると思う場所を地図上でタップする
- 正解の位置との距離で判定・採点する
- 判定後、正解の駅名・位置と、その駅を通る路線を地図上に表示する
- 未決事項：正解とみなす距離、距離に応じた点数

### FR-03 難易度（決定）

出題する路線と、予想するときの地図の表示を難易度で変える。

| 難易度 | 対象路線 | 予想時の地図表示 |
|---|---|---|
| 初級 | 山手線と、そこから伸びるJRの主要路線 | 路線の線と駅の点を表示 |
| 中級 | 初級に加えて、東京メトロと都営地下鉄 | 路線の線だけ表示（駅の点は出さない） |
| 上級 | 全路線 | 路線の線も駅の点も表示しない |

- 未決事項：初級の「JRの主要路線」に含める路線の一覧

### FR-04 図鑑・スタンプ（決定）

- 予想に正解した駅にスタンプを押し、図鑑に集める
- 図鑑は路線ごとに一覧で見られる
- 1つの路線の駅（都内の駅）をすべて集めると、路線バッジがもらえる
- 図鑑で駅をタップすると、豆知識（FR-08）を読み返せる
- スタンプと路線バッジのデザインは、最初は図形・色・文字のシンプルなものにし、あとで差し替える（決定）

### FR-05 地図の塗り絵（決定）

- スタンプを押した駅のまわりに色がつく
- 覚えた範囲が、東京の地図上で一目でわかるようにする
- ホーム画面の背景に表示する

### FR-06 イベントマス（決定）

すごろくの途中で、ランダムにイベントが起きる。

- 「寄り道したくなった！」：1駅戻る
- 「もう1回！」：もう一度サイコロを振れる
- 「乗り換えチャンス！」：乗換駅でなくても、近くの別路線に移れる

補足：

- 「快速に乗った！」は、快速・急行の停車駅データが必要になるため、初期版では見送る
- 未決事項：イベントの出現頻度、「乗り換えチャンス」で移れる路線の条件

### FR-07 ゴール後のルート表示（決定）

- 自分が通ったルートを地図上に表示する
- 最短ルートも並べて表示し、「こう行けば早かった」とわかるようにする
- 未決事項：「最短」の定義（駅数が最少か、乗り換えが最少か）

### FR-08 駅の豆知識（決定）

表示する場所：

- 予想に正解したとき、スタンプと一緒に表示する
- 図鑑から読み返せる

内容の方針：

- 土地勘が目的なので、位置の手がかりになる知識を優先する
  - 位置の手がかり：「隅田川のすぐ西」「山手線で新宿と池袋のほぼ中間」など
  - 街の特徴：「大学が多い学生街」など
  - 駅名の由来
- お店の名前や閉店する可能性がある施設など、変わりやすい情報は載せない

作成の流れ：

1. 駅データから対象駅の一覧を作る
2. AIで豆知識を下書きする。自信がない内容には「要確認」の印をつけ、根拠にした情報源も記録する
3. 人が事実を確認する（自治体や鉄道会社の公式サイトなど）
4. 確認済みのものだけアプリに表示する

進め方（案）：

- 初期版は山手線など主要駅から豆知識を用意する
- 豆知識がまだない駅は、「〇〇区」「通る路線」などデータから作れる情報だけを表示する

著作権：

- Wikipediaなどの文章はそのまま使わず、自分の言葉で書く（Wikipediaの文章を使う場合はCC BY-SAの条件を守る必要があるため）

### FR-09 間違いの報告（決定）

- 豆知識や駅データの間違いを、利用者が報告できるボタンを置く
- 未決事項：報告の受け取り方法

### FR-10 進捗の保存（案）

- 初期版はログインなしで、端末（ブラウザ）に保存する
- 保存するもの：スタンプ、路線バッジ、塗り絵の状態、遊び方を見たかどうか
- 設定画面から進捗をリセットできる

## 6. 画面構成（決定）

| No | 画面 | 内容 |
|---|---|---|
| 1 | ホーム | 塗り絵マップを背景に、「すごろくを始める」「図鑑」ボタンを置く |
| 2 | ゲーム準備 | 難易度を選ぶと、お題（ゴール駅）とスタート駅が決まる |
| 3 | すごろくプレイ | 地図が画面の大部分を占め、下にサイコロと現在地を表示する |
| 4 | 止まる駅の予想 | 地図上をタップして答える。判定後にスタンプの演出と豆知識を表示する |
| 5 | イベントマス | プレイ画面の上にポップアップで表示する |
| 6 | リザルト | ターン数、点数、通ったルートと最短ルート、今回もらったスタンプを表示する |
| 7 | 図鑑 | 路線ごとに駅スタンプと路線バッジを一覧表示する。駅をタップすると豆知識を表示する |
| 8 | 遊び方 | 初回だけ表示するチュートリアル。あとから設定画面でも見られる |
| 9 | 設定・情報 | 進捗のリセット、データの出典表記、利用規約 |

画面の流れ：

```
ホーム → ゲーム準備 → すごろくプレイ ⇄ 止まる駅の予想 → リザルト → ホーム
                        （イベントマスは途中で割り込む）
ホーム → 図鑑 / 遊び方 / 設定・情報
```

## 7. データ要件

### 7.1 駅・路線データ

すごろくと位置クイズのために、次の情報が必要。

- 駅：駅名、読み、緯度経度、所在の区市町村、都内か都外か
- 路線：路線名、事業者、路線カラー、線路の形（地図に線を引くため）
- 駅の並び順：路線ごとの駅の順番（すごろくで進むため）
- 乗換：どの駅とどの駅が乗り換えでつながっているか（同じ駅名でも事業者ごとに別の駅として持つ場合があるため）

データ元の候補：

- 国土数値情報（鉄道データ）：駅の位置や線路の形がある。駅の並び順は自分で整える必要がある
- 駅データ.jp：駅の並び順がある。公開アプリでの利用条件を確認する必要がある

未決事項：採用するデータ元（利用条件を確認してから決める）

調査メモ（検索結果をもとにまとめたもの。各サイトの規約本文で要確認）：

| データ元 | わかったこと | 使い道 |
|---|---|---|
| 駅データ.jp | 商用・非商用を問わず使えるとされている。会員登録（無料）が必要。路線カラーなど一部は有料 | 駅の並び順、隣の駅、乗換 |
| 国土数値情報（鉄道データ） | 出典を書けば商用でも使える | 線路の形（地図に線を引く） |
| 公共交通オープンデータ（ODPT） | 事業者ごとにライセンスが違う。JR東日本のデータはコンテスト参加者だけが使えるライセンス | 一般公開のアプリには向かない |

- 有力な組み合わせ：駅データ.jpで駅のつながりを作り、国土数値情報で線の形を描く
- 規約本文で確認すること：
  - 駅データ.jpのデータを加工してアプリに入れ、配信してよいか（再配布にあたるか）
  - 駅名の読み仮名が無料版に含まれているか
  - 出典の書き方

### 7.2 豆知識データ

形式の例：

```json
{
  "station": "高田馬場",
  "ward": "新宿区",
  "location_hint": "山手線で新宿と池袋のほぼ中間",
  "feature": "早稲田大学が近く、学生の多い街",
  "name_origin": "江戸時代、馬の訓練をする馬場があったことから",
  "sources": ["参照したURL"],
  "status": "要確認"
}
```

- `status` は `要確認` または `確認済み`
- アプリには `確認済み` のものだけ表示する
- 上の例の内容も、実際に使う前に事実確認が必要

## 8. 非機能要件

- スマホの縦画面を基本にする。PCでも表示が崩れないようにする
- 読み込みが速く、通信が弱い場所でも動きやすくする（PWA対応を検討）
- 一般公開するので、無料または安い費用で運用できる構成にする
- 見た目はかわいい雰囲気にする

## 9. 公開にあたっての制約

- **地図**：駅名や文字が書かれていない地図を使う（答えが見えてしまうため）
- **地図の出典**：OpenStreetMapや地理院地図などを使う場合、出典表記が必要
- **駅データの出典**：採用したデータの利用条件に従い、出典を表記する
- **デザイン**：鉄道会社の路線図やロゴはそのまま使わず、オリジナルの見た目にする
- **利用規約**：公開前に用意する

## 10. 初期版で対象外にするもの

- ユーザー登録・ログイン
- ランキング
- 運行情報、乗換検索
- 快速・急行など、列車の種別による停車駅の違い
- 都外の駅の出題
- 中級・上級（初期版は初級だけで公開し、中級・上級はあとから追加する）（決定）

## 11. 検討したが採用しなかった案（将来の候補）

- お迎えクイズ：「いま〇〇駅にいるよ！」と言われ、地図で場所をタップして迎えに行く
- 待ち合わせクイズ：2つの駅の中間の駅を当てる
- 3ヒントクイズ：ヒントを1つずつ出して駅を当てる
- 乗り換えパズル：路線カードを並べてルートを組み立てる
- 方角クイズ：ある駅から見た別の駅の方角を答える
- 今日の1問：全員に同じ問題を出し、結果をSNSでシェアできる
- タイムアタック：60秒で何駅当てられるか

## 12. 技術構成（案）

山手線だけの試作品で動かしてみて、問題がなければ確定する。

| 項目 | 案 | 理由 |
|---|---|---|
| 画面 | React + TypeScript + Vite | 使う人が多く、困ったときに調べやすい |
| 地図 | MapLibre GL JS ＋ ベクトルタイル（地理院ベクトルタイルなど） | 12.1を参照 |
| 駅・路線データ | 静的なJSONで配信する。元データをJSONに変換するスクリプトもリポジトリに置く | 都内だけなら数百KB程度の見込みで、APIサーバーはいらない |
| 進捗の保存 | localStorage（ブラウザの保存領域） | 保存するのはスタンプ程度で、量が少ない |
| PWA | vite-plugin-pwa | 通信が弱い場所への対応がしやすい |
| ホスティング | Cloudflare Pages（またはGitHub Pages） | 静的サイトなら無料で公開できる |
| 間違いの報告 | 初期版はGoogleフォームへのリンクにする | サーバーを用意せずに済む |

### 12.1 地図

- 上級では「路線の線も駅の点も表示しない」必要がある（FR-03）
- 画像で配信される地図（ラスタータイル）は、線路が最初から描き込まれているので消せない
- ベクトルタイルなら、文字・線路・駅を層（レイヤー）ごとに消せる。色も自由に変えられるので、かわいい見た目にもしやすい
- 下地の地図には文字・線路・駅を出さない
- 路線の線と駅の点は、下地の地図のものを使わず、駅データから自分で描く。こうすると、難易度ごとに線や点を出すか出さないかを切り替えられる
- 未決事項：採用するタイル（地理院ベクトルタイル、OpenStreetMapをもとにしたタイルなど）と、その出典表記

### 12.2 駅・路線データの持ち方

- 元データ（7.1）を変換スクリプトでJSONにし、アプリと一緒に配信する。元データが更新されたら、スクリプトを実行し直して作り直す
- 路線は一本道とは限らない（山手線は環状、丸ノ内線は途中で方南町方面に分かれる）。そのため、駅の並びは「隣の駅とのつながり」で持つ
- この形にしておけば、すごろくで進む方向を選ぶ処理にも、最短ルートの計算（FR-07）にもそのまま使える

## 13. 進め方（決定）

- 作業はGitHubのissueで管理する。全体の流れは[ロードマップ（#1）](https://github.com/k-m7m/tochikan/issues/1)にまとめた
- 実装はClaudeが担当し、PRを出す。PRの確認と、実際に遊んでの確認はオーナーが行う
- ブランチは「作業ブランチ → PR → main にマージ」で運用する
- 初期版は初級だけで公開し、中級・上級はあとから追加する
- 最初に山手線だけの試作品を作り、遊びが面白いか、スマホで操作しやすいかを確かめる
